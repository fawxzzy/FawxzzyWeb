# Public project-board source boundary

`/projects` provides the four requested display boards: Fitness, Mazer, Fawxzzy Web, and Atlas Stack. The committed JSON is an empty, dated placeholder with `publicationReady: false`. It contains no actual card, lifecycle, owner, dependency, or result record. The page says that approved card content and live synchronization are pending and is excluded from search indexing.

`src/data/project-board-adapter.mjs` is a local source seam for a future authorized public projection. It validates exact board and card fields, source identity, revisions, real calendar dates, scalar string fields, generation time, publication readiness, and health. A validated healthy nonempty snapshot can be supplied to the renderer by an eventual approved caller. Exact repeats are idempotent. Forked or backdated revisions show last accepted data as non-authoritative. Invalid, incompatible, and unavailable responses expose no cards. The empty placeholder is accepted only as an unapproved initial preview; it cannot become a healthy public projection.

`src/data/project-board-public-read.mjs` is an inactive, one-shot HTTP reader source seam. `createPublicBoardReader(initialState)` is disabled and makes no request. An eventual approved caller must explicitly inject both a public URL and a fetch implementation, then call `refresh()`; this repository supplies neither a default URL nor a caller. A disabled configuration also makes zero requests. Each enabled read omits credentials, refuses redirects, requires a JSON 200 response, bounds response size and request time, and passes decoded envelopes to the existing adapter. Transport and decode failures hide cards while preserving the last accepted snapshot and freshness privately. Concurrent and late reads cannot replace a newer result. The local size and timeout bounds are source safety limits, not an adopted platform response contract.

Projects navigation stays visible without signing in and points to the account origin, where the same public page can see the existing browser Auth session. The page renders the public board shell and the existing private Operations observation in one place. On the exact account origin, an already signed-in browser checks the private reader once; a definite missing-session denial may open one caller-bound session and read once. Uncertain responses do not retry or reveal cards. The private observation is client-only, short-lived, and never serialized into the public page HTML or public board snapshot. Signed-out users and other authenticated subjects receive no private cards. The private section does not invent canonical private board membership: the current Operations projection exposes cards without a board map. A protected owner-approved board mapping and installed reader remain needed for actual private board tabs. The former `/operations` path is only a static-export-compatible client redirect to `/projects`; it renders no separate work overview or private data.

The private server endpoint additionally requires a server-only `OPERATIONS_OWNER_SUBJECT` UUID matching the current master-verified Auth subject before touching the RPC. Missing or mismatched binding fails closed; local browser fixtures use dummy subjects. The existing Auth/session-bound RPC grant is still required. No provider setting or real account session is changed by this source. Only the protected owner may establish the actual subject binding, installed RPC/API exposure, login journey, and live acceptance.

The repository still has no active public projection transport, polling loop, board writer, reverse editor, or database client for this view. The adapter's envelope is not an adopted platform API. Test-only synthetic cards exercise status changes, relationships, privacy rejection, and detail selection; they are not current project work. Actual public fields and prose require their owners' approval before entering repository source. Private operator records stay with their canonical writer and must not be serialized into public HTML, public board snapshots, or shared caches.

The current adapter requires `previousRevision` to match the last accepted revision. A cold client at `projectionRevision: null` cannot accept a latest-only envelope with `previousRevision: r2`; a client at `r1` cannot accept `r3` with `previousRevision: r2`. Both remain reconciling. The canonical Platform owner must adopt sanitized public response, identity, bootstrap and missed-revision recovery semantics, the actual public URL or artifact, and refresh policy before this reader can be connected. The source does not bypass its stale/fork guard or assume a latest-snapshot read is sufficient. The existing card writer and one approved real card remain prerequisites for a source-to-page/result-return acceptance. Source publication, deployment, and that real-card acceptance are separate gates. The current source establishes UI, validation, and an inactive reader behavior only.
